# E2E-проверки

Скрипты на Playwright: проходят приложение в настоящем браузере и складывают
скриншоты. Нужен запущенный сервер и база с демо-данными (`npm run db:seed`).

```bash
npx playwright install chromium        # один раз
BASE_URL=http://127.0.0.1:3100 AUTH_PASSWORD='ваш-пароль' node e2e/flow.mjs
```

Dev-сервер для прогонов: страницы компилируются на первом заходе, это десятки
секунд, поэтому в новых сценариях таймауты 90 с:

```bash
APP_URL=http://localhost:3100 npx next dev -p 3100 -H 0.0.0.0
```

## Переменные

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BASE_URL` | `http://127.0.0.1:3100` | адрес запущенного приложения |
| `AUTH_PASSWORD` | — (обязательна) | пароль, которым вы входите в приложение |
| `SHOTS_DIR` | `e2e/screenshots` | куда складывать скриншоты (старые сценарии) |
| `E2E_BASE` | — | старое имя `BASE_URL`, ещё принимается |

Пароль и адрес в скриптах не зашиты: без `AUTH_PASSWORD` скрипт сразу
останавливается с подсказкой. Пароль берётся не из `.env`, а из переменной
окружения — он же задаётся при первом запуске приложения. Каталог скриншотов
в `.gitignore`.

Адрес у всех сценариев один — `BASE_URL`. Старое имя `E2E_BASE` читается как
запасное, чтобы не ломать прежние команды в переписке и handoff.

## Скрипты

Основной путь:

| Скрипт | Что проверяет | Меняет данные |
|---|---|---|
| `flow.mjs` | объект → муфта → кабели → прямая сварка → документ | да |
| `cold-start.mjs` | создание с нуля, дубль номера, ручная сварка, защита от повтора | да |
| `share.mjs` | фото, метки, публичная ссылка, доступ к файлам | да |
| `sign-in.mjs` | не сценарий, а общий вход: на пустой базе задаёт пароль и продолжает | — |

Возможности 0.6.0:

| Скрипт | Что проверяет | Меняет данные |
|---|---|---|
| `coordinates.mjs` | ввод координат одной строкой, сохранение, карта | муфту |
| `copy-link.mjs` | «Копировать» на HTTP-адресе, где нет Clipboard API | ссылки |
| `pdf-coordinates.mjs` | координаты и история в настоящем PDF | нет |
| `share-scope.mjs` | ссылки на объект и на муфту, границы доступа, файлы | ссылки |
| `guest-edit.mjs` | имя гостя, правка от его имени, история, возврат, read-ссылка | муфту, историю, ссылки |
| `fiber-label.mjs` | подпись волокна: редактор, чип, история, PDF | волокно, историю |

После 0.6.0:

| Скрипт | Что проверяет | Меняет данные |
|---|---|---|
| `trace.mjs` | трасса волокна: вкладка, выбор жилы, маршрут, концы, переход из карточки | нет |
| `mobile-ui.mjs` | телефон: форма «Новая муфта» целиком на экране; тема гостевой ссылки — светлая по умолчанию, переключается и запоминается | муфту, ссылки |

`trace.mjs` только читает схему: он строит маршрут по первому волокну объекта
и проверяет, что оба конца маршрута объяснены. Запускать его можно на любой
базе, восстановление после него не нужно.

`pdf-coordinates.mjs` и `fiber-label.mjs` требуют `pdftotext` (пакет
`poppler-utils`) — им проверяется текст готового PDF, а не скриншот.

Сценарии 0.6.0 кладут снимки в `/tmp/opencode` (так удобнее на сервере, где
репозиторий не должен засоряться) и `SHOTS_DIR` не читают.

## Пароль, адрес и снимки

Все сценарии берут настройки из `e2e/env.mjs`, и правило одно:

| Что | Порядок |
|---|---|
| Адрес | `BASE_URL`, потом `E2E_BASE`, потом `http://127.0.0.1:3100` |
| Пароль | `AUTH_PASSWORD` из окружения, иначе строка из `.env` |
| Снимки | `SHOTS_DIR`, потом `/tmp/opencode` |
| Объект | по имени «ЖК «Северный», корпус 3» из сида |

Раньше новых сценариев это касалось иначе: они читали `.env` напрямую и
падали, если файла нет. В CI `.env` не существует — пароль приходит из
окружения, а на рабочем сервере он записан в `.env`, и повторять его в
командной строке не нужно.

Объект тоже ищется по имени, а не «первый в списке». Причина: список
отсортирован по времени изменения, и `cold-start` создаёт свой объект, который
становится первым. Без этого поиска все следующие сценарии молча работали бы
не с тем объектом.

## Тестовая муфта и восстановление

Сценарии `guest-edit`, `fiber-label`, `coordinates` правят настоящую муфту —
ту, что первая в списке объектов. На рабочем сервере это
`cmwsw36dk0002cr2kyers04xx` («Коцюбинского 26А»), её исходное состояние:

| Поле | Значение |
|---|---|
| `status` | `DONE` |
| `notes` | `Опора напротив серых ворот` |
| `lat`, `lng` | `44.95398`, `34.12554` |
| подпись волокна | нет |

После прогонов вернуть и убрать следы:

```bash
docker exec fiber-db psql -U fiber -d fiber -c "
update \"Closure\" set status='DONE', notes='Опора напротив серых ворот',
  lat=44.95398, lng=34.12554 where id='cmwsw36dk0002cr2kyers04xx';
update \"Fiber\" set label=null where label='Абонент: кв. 42, Петров';
delete from \"ClosureEvent\" where \"closureId\"='cmwsw36dk0002cr2kyers04xx';
delete from \"ShareLink\" where \"createdAt\" > now() - interval '3 hours';
"
```

Перед прогонами на живых данных — `npm run backup`.
