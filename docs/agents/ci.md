# Проверки и CI

Два места проверок, и они не дублируют друг друга.

## GitHub Actions (`.github/workflows/ci.yml`)

Запускается на каждый push в `main` и на каждый PR. Две джобы.

### `check` — required check для защиты ветки

1. `npm ci`, `prisma db push` на сервисном Postgres;
2. шаблон `.env` обязан требовать заполнения (защита от настоящих секретов
   в `.env.example`);
3. `npm test` — юнит-тесты;
4. `npm run lint` — ESLint, конфиг `eslint.config.mjs`;
5. `npm run build`.

### `e2e` — все десять сценариев

`needs: check`, то есть запускается только если базовые проверки прошли.
Postgres-сервис, `prisma db push`, production-сборка, `next start` на
`127.0.0.1:3000`, Chromium и `poppler-utils` (нужен `pdftotext` двум
сценариям про PDF).

Порядок сценариев — не случайный:

1. `cold-start` — на пустой базе, проходит мастер первого запуска;
2. `npm run db:seed` — данные для остальных;
3. `flow`, `share`, `coordinates`, `copy-link`, `share-scope`, `guest-edit`,
   `fiber-label`, `pdf-coordinates`, `trace`.

Сценарии идут последовательно: у них одна база, и каждый следующий видит
работу предыдущего. Параллелить нельзя.

При падении в артефакты `e2e-failure` попадают снимки (`/tmp/shots`) и лог
сервера (`/tmp/server.log`). На зелёном прогоне их нет — незачем хранить.

Смотреть только упавшее:

```bash
gh run list --limit 3
gh run view <id> --log-failed
```

Полный лог читать не нужно: в нём сотни строк про кеш npm и слои сборки.

## Что остаётся локально

| Проверка | Почему локально |
|---|---|
| `npx tsc --noEmit` | секунды, ловит ошибки типов до пуша |
| `npx vitest run <файл>` | секунды на изменённый модуль |
| Живая сборка (`BASE_URL=...`) | только то, чего нет на сиде: реальные данные объекта, HTTP без TLS, гостевые ссылки |

**`npm run build` локально не запускать.** На сервере 4 ГБ ОЗУ, сборка с
Playwright и боевым приложением одновременно упирается в OOM, а `.next`
перезаписывается под работающим сайтом. Сборку проверяет CI.

## Что в CI не уезжает

- **Бэкапы базы.** Репозиторий публичный, в дампе адреса и заказчики.
- **Проверки на живых данных.** Именно они нашли дыру доступа по ссылке на
  объект и расхождение подписей концов кабеля в трассе — на синтетическом
  сиде такого нет.
